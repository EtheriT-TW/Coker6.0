## 手動驗證及執行順序

僅在正式資料庫還原出的隔離副本操作；先依既有流程停止會寫入此副本的 MVC、Public、Platform、HangFire 與 Provisioning Worker。三份腳本的資料庫名稱檢查只能比對名稱，無法辨識同名資料庫是否為正式環境，請自行確認 SSMS 的伺服器及連線。

1. **第一步**：開啟 `刪除其他網站.sql`，核對 `USE`、`@ExpectedDatabase`、網站 23／36 與 `@DeliveryAdminUsers`。預設 `@Execute=0` 只做結構與帳號檢查；通過後，手動改為 `1` 才清理並提交。這一步不是回滾演練。檢查最後網站、會員、商品與訂單筆數，以及保留網站的重要資料有無誤刪。
2. **第二步（含自動備份）**：開啟 `刪除其他網站step2資料清洗.sql`，核對資料庫、交付帳號、`@AuditUserId` 及 `@MasterBackupDirectory`。`@RunCleaning=0` 只檢查；`@RunCleaning=1, @DoCommit=0` 執行清洗演練並回滾，不產生備份。正式處理設 `@RunCleaning=1, @DoCommit=1`：清洗檢查成功 → 提交 Coker6 → 自動產生唯一檔名的 `_SanitizedMaster_日期時間_GUID.bak` → `RESTORE VERIFYONLY WITH CHECKSUM` → 在 Coker6 登記已驗證路徑。看到 `VerifiedMasterBackupFile` 及「母版備份及驗證完成，可直接執行第三步」後才繼續，不必另做手動備份。備份目錄必須已存在，SQL Server 服務帳號須有寫入權限。
3. **第三步**：開啟 `刪除其他網站step3產生交付備份檔.sql`，保持 `@SourceBackupFile=NULL`、`@MasterDatabase=N'Coker6'`，就會在同一 SQL Server 自動取得第二步登記的路徑；核對輸出目錄、工作資料庫及交付帳號清單。`@Execute=0` 只檢查設定及顯示計畫，不查母版路徑或驗證母版內容；設 `1` 才自動讀取路徑、完整驗證備份、刪除／重建 `Coker6_Delivery_Work`、還原、檢查、整理帳號、產生各別 `.bak` 並執行 `RESTORE VERIFYONLY`。第三步不改寫或刪除 Coker6；預設最後刪除工作資料庫。需要檢查最後一份時，可先設 `@KeepLastWorkingDatabase=1`。若跨伺服器或另選母版，仍可手動指定 `@SourceBackupFile` 的完整路徑，母版一樣必須通過清洗檢查。
4. **驗收交付檔**：手動將每份新備份還原至另一個隔離資料庫，確認只有指定 Users 帳號、網站只有 23／36、訂單／物流／會員／聯絡表單顯示測試資料、工作和歷史紀錄為空；測試登入、商品、訂單、紅利、行銷贈品、版面、圖片與附件。`RESTORE VERIFYONLY` 不代表應用功能或匿名化已完整驗收。

第二步每次正式提交都會撤銷上一輪自動母版路徑，只有新備份及驗證成功才重新登記，不會覆寫舊母版檔案。如果備份、驗證或路徑登記失敗，清洗已經提交，不能回滾成清洗前的資料；訊息會明確說明失敗階段。修正目錄、權限或磁碟空間後，可重新執行第二步完成清洗與備份。未完成／未驗證的檔案不會被第三步自動選取。

第一、二步清洗會刪除／改寫資料，第二步還會產生並驗證完整母版備份；第三步會讀寫大型備份與工作資料庫。三者實際執行都可能超過 30 秒，且需要足夠磁碟及交易記錄空間；耗時取決於副本大小、SQL Server、硬碟及鎖定情況，無法可靠預估。本次未代為執行。

## 保留範圍與交付前人工檢查

- 延續舊腳本規則：指定交付管理者的帳號、密碼和基本資料保留，只撤銷重設密碼權杖；因此請確認這些帳號本來就是可以交付的帳號。第三步只保留當份指定的管理者。
- 會員 UUID、訂單及紅利關聯保留。會員原密碼失效；電話改固定測試值，姓名、信箱與地址換測試資料。
- 網站展示內容、名稱、原本的 `Websites.DefaultUrl`、HTML／CSS、商品／文章／版面 JSON，以及圖片／附件檔名依原規則保留；它們可能包含人工填寫的聯絡資訊或外部連結，交付前仍需檢查。平台網域及替代網址已改測試值，實際驗收時需配合隔離環境網址設定。
- SQL 清洗不檢查圖片、附件或實體檔案內容，也不處理應用程式設定檔中的正式金鑰。清洗屬於邏輯資料處理，不宣稱達到備份媒體的鑑識級抹除。
